# 逆向证据记录模板

这个模板用于在依据逆向结论修改包装层之前，先把某个函数、调用链或小切片的逆向证据固定下来。

使用原则：

- 一次只记录一个足够小的主题，例如“单个函数”“一条调用链”“一个明确状态转换”。
- 优先引用具体函数、地址、指令区间、调用点，不要只写“看了 strings / symbols / 某个大文件”。
- `Confirmed` 只写已有机器码、伪代码、运行结果直接支持的结论。
- `Inferred` 只写暂时推断出的行为，并明确它依赖哪些证据、还缺什么。
- 包装层中依据本记录实现的语义，其实现附近的注释应回指这里列出的具体函数锚点。

## 标题

- 建议格式：`<binary> <topic>`
- 例：`moresampler.exe desc.mrq locking`

## 逆向锚点

- 函数:
  - `00401234 FUN_00401234_someName`
  - 作用一句话:
- 调用链:
  - `FUN_A -> FUN_B -> FUN_C`
- 关键地址 / 指令区间:
  - `00401280 - 004012a6`
- 相关数据:
  - `DAT_00xxxxxx`

## 证据来源

- Ghidra 伪代码:
  - `decomp/<file>.c`
- 汇编核对:
  - 哪几条指令 / 哪个基本块
- 运行时观察（实测）:
  - 如有，则记录步骤、所用程序与样本（`work/` 下的副本，或 `moreloader --trace` 的输出）、现象、关键值
- 公开资料:
  - 如有，则给出链接与提交（例如 mingw-w64 的 `crtexe.c`、winpthreads、Wine 的 `dlls/msvcrt`、Sleepwalking/libllsm）
- msvcrt 探针（实测）:
  - 如有，则记录探针程序、调用参数与 `msvcrt.dll` 的版本
